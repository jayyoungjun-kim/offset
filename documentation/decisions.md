# 의사결정 기록

## 2026-09-07 / 첫 제품 범위
- 확정: 리스트·상세·어드민·로그인·회원별 신청. 홈과 About 리뉴얼 및 공지 공개는 후속 단계.
- 근거: 사용자의 순서와 현재 서비스의 단일 워크숍 모델.
- 원칙: 아직 없는 프로그램이나 성과를 가상으로 공개하지 않는다.

## 시각적 방향
- 확정: 넓은 프로그램 인덱스, 흰색/잉크/블루, SUITE와 기존 로고, 카드와 숫자 중심.
- 근거: Wanted의 탐색/결정 구조를 교육 맥락으로 해석하고 기존 OFFSET 브랜드를 이어간다.

## 데이터와 인증
- 확정: 기존 Workers + D1. Google OAuth authorization code + PKCE와 state. opaque session, 해시 저장.
- 관리자: 서버에서 이메일 allowlist 확인. 운영자 화면 미리보기는 저장 불가, 개인정보 없음.
- 공개용 데모 로그인은 만들지 않는다. 실제 로그인 검증은 자격 정보 설정 후 진행한다.

## 과거 신청 경로
- `/apply`는 새로운 상세로 이동한다. 기존 API의 POST는 새 회원 기반 신청 로직으로 연결한다. 파일 첨부 대신 웹 링크를 받는다.
- 이유: 익명 신청·별도 Google 스프레드시트 저장으로 회원 신청이 분산되는 경로를 제거한다.
- 사용자의 Google Apps Script 수정은 보존하며 실제 알림 발송은 이번 작업에서 실행하지 않는다.

## 배포와 검증
- 기존 Pages 배포로는 서버 기능이 동작하지 않는다. 정적 배포를 성공으로 오인하지 않도록 D1 프로젝트의 정적 내보내기를 차단한다.
- 통합 검증은 Worker 런타임과 격리된 DB로 실행한다. 기존 HTML 렌더 검증도 그 런타임으로 이동한다.
- 이번 작업에서는 운영 사이트를 변경하지 않는다.

## 미결
- 실제 OAuth 자격 정보·운영자 메일.
- 개인정보 보관 1년은 초안. 실제 고지와 정기 삭제·탈퇴 워크플로를 운영 전 확정.
- 결제, 자동 알림, 수강 콘텐츠, 정원 자동화, 배포 환경 전환.

## 2026-09-07 / QA 서버 배포
- 사용자 요청: qa.offset.quest에서 개발·검증한 뒤 완성 시 운영에 배포.
- 기존 Sites 프로젝트에 qa.offset.quest와 활성 SSL이 이미 연결되어 있어 재사용한다.
- QA 런타임에 SITE_ENV=qa, AUTH_ORIGIN=https://qa.offset.quest 적용.
- 기존 운영 사이트가 같은 서버의 기본 호스트로 신청 API를 호출하는 의존성을 확인. 기본 호스트+운영 Origin의 요청에만 구형 처리 유지, QA 요청은 새 D1과 Google 회원 신청으로 분리.
- 운영 분석과 상담 위젯을 QA에서 실행하지 않으며 검색 엔진 제외와 QA 표시를 제공.
- GitHub 운영 자동 배포를 비활성화. 완성 후 별도 운영 서버/DB와 명시적인 출시 절차 사용.
